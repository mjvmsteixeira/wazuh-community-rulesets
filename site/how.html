How it works

The registry collects 16,586 Wazuh rules from 115 community sources, in 479 packs, and measures each one on a real wazuh-manager v4.14.8. The search page warns when a pack can silence other rules. This page explains how those warnings are worked out, and how far each one is proven.

Sibling rules

Rules that hang off the same parent (if_sid, or if_group on every rule already loaded whose groups contain the pattern) compete for each event, and only one wins. Measured on the engine: level-0 siblings are evaluated first, then the others by level, highest first, and on a tie by the file loaded first. A rule with no conditions of its own (a catch-all) always matches, so it takes every event that reaches it, and the siblings after it never alert. wazuh-analysisd -t does not warn.

Try it with a real Sysmon event and two real packs. Tick and untick the packs to see the evaluation order change.

Evaluation order

    Load order

    The engine sorts all rule files by name, official and custom mixed. A pack installed with its original file name, such as the 02-rules.xml of a Wazuh blog post, loads before the official files: the official parents of its if_sid do not exist yet, the engine warns (7617) and the rule loses that condition.

    The install script on the search page, and every test in the registry, name each file <pack-prefix>__<file>. That also stops two packs from overwriting each other's files, and each pack's CDB lists go to etc/lists/<pack-prefix>/, so a pack's audit-keys no longer replaces the official one.

      What the tests found

      Results with proof, from the current run. The files behind them are on GitHub, where they open as searchable tables.

      A Sysmon pack installed alone removes the official T1059.003 detection (92032).

      Its rule 101101 “Process creation” has level 5 and no conditions, so it takes every Sysmon event 1 before 92032 and 15 official rules in total. Proven with an injected event. catalog/catchall_silences_official.csv

      A level-0 grouping rule sits in front of 12 official web detections.

      MORGADO01 rule 100513 was written to feed a correlation, but level-0 siblings are evaluated first, so it takes the events of 31101 and 30101.

      921 rules in 48 packs lose events to official siblings in some situations.

      Reported in issue #1: a child of 5715 (SSH login accepted) below level 12 loses the login to 40112 after several failures from the same IP. 40112 has no if_sid; it is a sibling through if_group. catalog/conditional_shadows.csv

      1,884 rule IDs are defined differently by several sources.

      Installed together, only the definition loaded first exists. In the pair test this cost 333 samples. catalog/id_conflicts.csv

      The same pack can behave differently depending on the manager's CPU.

      A regex with a non-ASCII dash matched on arm64 and not on amd64. 19 rules have conditions like that; the CI runs on amd64, like most managers.

      A pack can depend on loading before the official files.

      hawkteam404/opnsense names its file 0454-opnsense_decoders.xml to load before the official filterlog decoder. Installed with the pack prefix, the official decoder takes the logs; the pack needs decoder_exclude.
